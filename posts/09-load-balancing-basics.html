Load Balancing Basics: Round Robin vs Least Connections

A load balancer sits in front of a group of servers and decides which server handles each incoming request. Its job is to prevent any single server from being overwhelmed while the others sit idle — a core building block of availability at scale.

Round robin is the simplest strategy: requests are handed out to servers in a fixed rotating order, one after another. It's easy to implement and works well when every server has roughly equal capacity and every request takes roughly the same amount of work.

Least connections is more adaptive: the load balancer sends each new request to whichever server currently has the fewest active connections. This handles uneven workloads better — if one server is stuck processing a few slow requests, round robin would still send it new traffic, while least connections routes around it.

Key takeaway: round robin is simpler and fine for uniform workloads; least connections adds a bit of overhead but responds better to real-world traffic that isn't evenly distributed. Most production load balancers support both, along with more advanced strategies layered on top.
